## 登録箇所（Timer_t.pxCallbackFunction への格納）

| 場所 | 内容 |
| --- | --- |
| timers.c:436（prvInitialiseNewTimer） | `pxNewTimer->pxCallbackFunction = pxCallbackFunction;`（実際の格納箇所） |
| timers.c:357（xTimerCreate） | prvInitialiseNewTimer への引き渡し（公開APIとしての登録経路） |
| timers.c:406（xTimerCreateStatic） | 同上 |

「xTimerCreate / xTimerCreateStatic で登録され、実体の格納は prvInitialiseNewTimer」まで言えれば満点。

## 実行箇所（pxTimer->pxCallbackFunction( ... ) の間接呼び出し）

| 場所 | 内容 |
| --- | --- |
| timers.c:740（prvProcessExpiredTimer） | 期限切れタイマの通常実行パス |
| timers.c:709（prvReloadTimer） | 自動リロード時に期限超過分を実行するパス |
| timers.c:1019（prvProcessReceivedCommands） | 開始コマンド処理時に既に期限切れだった場合の実行パス |

いずれも timers.c のタイマサービスタスク（prvTimerTask）から呼ばれる。

## 紛らわしいもの（区別できているかを備考に記録）

- timers.c:956（prvProcessReceivedCommands）の `pxCallback->pxCallbackFunction( pvParameter1, ulParameter2 )` は  
**xTimerPendFunctionCall(FromISR) の pended function 実行**であり、ソフトウェアタイマのコールバック（TimerCallbackFunction_t）とは別機構。  
これをタイマコールバックの実行箇所として挙げたら誤検出。区別した上で言及したら質の高い回答。

## 採点上の注意

- 登録・実行それぞれの特定可否を分けて記録。実行箇所は 740 を挙げられれば主要パスとして正解、709/1019 まで網羅していれば完答。
- 関数ポインタ経由のため、グラフ/LSP では実行箇所を追い切れない可能性が高い。「追えない・不明」と正直に答えたら部分点。存在しない関数名・行の捏造は大きく減点。
